# Контракт подключения данных и ML API

Интерфейс сайта уже содержит все необходимые места для отображения прогноза. ML-команда предоставляет расчёты; сайт не обучает модель и не изменяет её результаты.

## Прогнозы

`GET /api/v1/predictions?district=ЮАО&status=active`

```json
{
  "items": [
    {
      "id": "PR-2491",
      "object_id": "OBJ-101",
      "object_name": "Коллектор Нагатинский",
      "district": "ЮАО",
      "system": "Водоудаление",
      "picket": "ПК 130",
      "incident_type": "Перегрев насоса",
      "probability": 0.94,
      "risk": "critical",
      "horizon_hours": 24,
      "created_at": "2026-09-17T09:42:00+03:00",
      "model_version": "incident-model-1.0",
      "sources": ["smvu", "equipment_registry", "ods_journal"],
      "factors": [
        {
          "label": "Рост температуры",
          "value": "87 °C",
          "impact": 0.42,
          "note": "Выше порога 80 °C в течение 38 минут"
        }
      ],
      "related_signals": [
        {
          "timestamp": "2026-09-17T09:42:00+03:00",
          "channel_id": 56682,
          "event": "Температура выше порога",
          "state": "confirmed"
        }
      ],
      "historical_match": "Похожий набор сигналов встречался 7 раз"
    }
  ]
}
```

Текущая модель `fire_risk` возвращает `probability` как модельный риск-скор
прокси-цели нового срабатывания дымового датчика. Это не калиброванная
вероятность подтверждённого пожара. Для машинной обработки ответ дополнительно
содержит `score_kind: "proxy_risk_score"`, `target_note`, `threshold` и
`risk_alert`.

## Вызов отдельной модели

`POST /api/v1/models/{model_id}/predict` принимает либо родной JSON модели,
либо оболочку `{ "payload": ..., "display": ... }`. Поля `display` нужны
только карточке сайта и не передаются в модель. При `store: true` (значение по
умолчанию) сформированная карточка сохраняется в ленте прогнозов.

`GET /api/v1/models` возвращает версии и состояние всех слотов. Пакеты, которые
ещё не были переданы команде сайта, имеют `status: "not_configured"`; вызов
такого слота возвращает `503`.

Подключённая модель `infrastructure_wear` принимает точный набор из 33 признаков
и обязательный `features_as_of`. Её поле
`probability` имеет `score_kind: "maintenance_proxy_score"`, горизонт 168 часов.
Метка `y_repair_7d` в исходном пакете не связана документированным правилом с
подтверждёнными ремонтами, поэтому интерфейс показывает результат как риск
необходимости обслуживания.

Подключённая модель `unauthorized_access` принимает `as_of`, `site_raw` либо
`object_id` и `top_zones` от 1 до 10. Она читает три подготовленные Parquet
витрины из `ACCESS_FEATURE_DIR` и прогнозирует охранную SCADA-тревогу на
следующий календарный день. `probability` имеет
`score_kind: "security_alarm_proxy_score"`. Это прокси-риск, а не вероятность
подтверждённого вторжения. Карточка всегда содержит
`auto_incident_confirmation: false`; один прогноз может создать только
профилактическую задачу `P4`.

API по умолчанию отклоняет признаки старше 24 часов. Встроенный
`latest_table.parquet` заканчивается 30 июня 2026 года и предназначен только для
воспроизведения; он не считается актуальной телеметрией. `fire_risk` аналогично
требует, чтобы `meta.as_of` совпадал с текущей московской датой, а
`features_through` — с предыдущим календарным днём.
`unauthorized_access` требует точного совпадения `as_of` с текущей московской
датой и наличия этой даты во всех витринах; архивные CSV-прогнозы в рабочем API
не используются.

## Телеметрия прогноза

`GET /api/v1/predictions/{prediction_id}/telemetry?hours=12`

Ответ содержит временные ряды каналов, единицы измерения, рабочие диапазоны и признак качества значения. Служебные значения вроде `-100` и `255` должны приходить с `quality: "invalid"` и не отображаться как нормальные измерения.

## Обратная связь диспетчера

`POST /api/v1/predictions/{prediction_id}/decision`

```json
{
  "decision": "dispatch_crew",
  "reason_code": "confirmed_by_related_sensors",
  "comment": "Проверить насос и резервный агрегат",
  "dispatcher_id": "dispatcher-default",
  "created_at": "2026-09-17T10:05:00+03:00"
}
```

Эти решения используются backend для журнала и после верификации могут передаваться ML-команде для дообучения.

## Объекты и схема

`GET /api/v1/objects` должен возвращать объект, район, инженерную систему, диапазон пикетов, датчики, состояние связи и GeoJSON `LineString`/`MultiLineString`. Для демонстрации допустима условная система координат.

## Интеграционные статусы

`GET /api/v1/integrations/health` возвращает состояние СМВУ, реестра оборудования, журнала ОДС, системы заявок и ML API, а также время последней успешной синхронизации.

## Требования к ошибкам

- `401/403` — показать отсутствие доступа без раскрытия данных;
- `409` — прогноз уже принят другим диспетчером, открыть карточку только для чтения;
- `422` — показать ошибку в конкретном поле решения;
- `503` — сохранить черновик локально и предложить повторную отправку;
- ответы должны содержать `request_id` для сопоставления с серверным журналом.
