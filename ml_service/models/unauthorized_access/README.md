# Модель «Несанкционированный доступ»

Интеграция создана из архива
`LCT26_Model3_Unauthorized_Access_FINAL_2026-09-19.zip`. Файлы архива прошли
проверку `MANIFEST.sha256`; исходные 26 тестов и `ruff` выполнены повторно в
окружении с зафиксированными авторами версиями зависимостей.

## Что прогнозируется

Единица прогноза — объект охранной подсистемы (`site_raw`) на календарную дату
`D`. Цель — наличие хотя бы одной SCADA-тревоги со значением
`Обнаружено движение` или `Не замкнут` на календарный день `D+1`. Горизонт —
24 часа. Это проверяемая прокси-цель, но не подтверждённое человеком
несанкционированное проникновение.

Три LightGBM-компонента используют только события, доступные до конца `D`:
историю физических и технических тревог, rolling/lag-признаки, недельную
сезонность, эпизоды тревог и причинный контекст соседних инженерных систем.
Второй ансамбль ранжирует до пяти наиболее вероятных зон внутри выбранного
объекта. Прогноз сам по себе создаёт только профилактическую задачу `P4` и
всегда требует независимой проверки.

## Честная временная проверка

Модели, веса и пороги выбирались на 2024–2025. Период 2026-01-01–2026-06-30
использован как финальный report-only holdout. После независимой пересборки OOF
добавлен режим `safety_margin_70_50`: он максимизирует худший запас над
Precision 0,70 и Recall 0,50 на обоих development-годах, без настройки по
holdout.

| Метрика | 2026H1 |
| --- | ---: |
| Precision | 0,7327 |
| Recall | 0,5426 |
| PR-AUC | 0,7490 |
| Тревог в сутки | 7,59 |

Требования Precision > 0,7 и Recall > 0,5 выполняются одновременно. В
календарном bootstrap из 5 000 повторов нижние границы 95% равны 0,7017 и
0,5103 соответственно. Полный
batch из 30 объектов и 1 031 зоны занимал в среднем 2,19 с, p95 — 2,47 с;
ограничение 5 минут выполняется с большим запасом. Эти числа относятся к
прокси-цели охранной тревоги. Качество по подтверждённым вторжениям неизвестно,
поскольку таких исходов в данных нет.

Проверяемые отчёты сохранены в `reports/`, а production inference-runtime — в
`runtime/lct26_access/`.

## Актуальные признаки

Архив не содержит готовых feature parquet, поэтому исторические примеры не
подставляются в рабочий API. Перед запуском нужно сформировать три таблицы:

- `daily_site_features.parquet`;
- `daily_family_context.parquet`;
- `daily_zone_features.parquet`.

Для CSV-журналов и актуальных справочников:

```bash
cd ml_service
python -m models.unauthorized_access.prepare_features \
  --catalog-dir /data/catalogs \
  --journal-csv-dir /data/journals \
  --work-dir /data/access-work \
  --output-dir live_features \
  --years 2019 2020 2021 2022 2023 2024 2025 2026
```

В Docker Compose `ACCESS_FEATURE_DIR=/app/live_features`; локально можно задать
эту переменную либо три отдельных пути `ACCESS_SITE_FEATURE_PATH`,
`ACCESS_CONTEXT_FEATURE_PATH`, `ACCESS_ZONE_FEATURE_PATH`.

## Вызов API

```json
{
  "payload": {
    "as_of": "текущая московская дата YYYY-MM-DD",
    "site_raw": "217-1",
    "top_zones": 5
  },
  "display": {
    "district": "ЦАО",
    "picket": "ПК 120"
  }
}
```

Запрос: `POST /api/v1/models/unauthorized_access/predict`. По умолчанию API
отклоняет любую `as_of`, которая не совпадает с текущей московской датой, и
ошибается, если в витринах нет этой даты. Для воспроизводимости архивного
периода проверку можно явно отключить только переменной
`ML_ALLOW_HISTORICAL_SCORING=1`.

Ответ содержит объектный скор, порог, дату прогноза, локальные вклады LightGBM,
top-зоны и безопасную политику реагирования. `zone_classifier_probability` —
условный скор зоны; несколько зон могут быть положительными, поэтому его нельзя
трактовать как взаимоисключающую вероятность.
