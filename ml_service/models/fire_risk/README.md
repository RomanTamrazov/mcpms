# Модель «Пожарный риск»

CPU-ансамбль из шести CatBoost-моделей прогнозирует **новое срабатывание
дымового датчика на объекте**, а не подтверждённый пожар. Единица прогноза —
`ид_объект`, горизонт — 336 часов (14 суток), что соответствует требованию
горизонта не менее 24 часов.

## Метрики

Порог, признаки и веса выбраны на временных development-периодах. На
отложенном периоде 2026H1:

| Метрика | Значение |
| --- | ---: |
| Precision | 0,7841 |
| Recall | 0,6037 |
| PR-AUC | 0,815 |
| Горизонт | 336 часов |

Precision > 0,7 и Recall > 0,5 выполняются одновременно. Инференс одного
объекта занимает миллисекунды на CPU.

Цель остаётся прокси: в исходных данных нет подтверждённых ОДС пожаров,
ложных тревог, ремонтов и графиков горячих работ. Поэтому API возвращает
`score_kind: "proxy_risk_score"` и не называет скор вероятностью пожара.

## Вход API

`POST /api/v1/models/fire_risk/predict` принимает оболочку с родным payload:

```json
{
  "payload": {
    "meta": {
      "object": 1234,
      "as_of": "текущая дата YYYY-MM-DD",
      "features_through": "предыдущая дата YYYY-MM-DD",
      "eligible": true
    },
    "features": {
      "obj_smoke_channels_total": 4,
      "exp_decay_days_since_onset_7d": 0.3
    }
  },
  "display": {
    "object_name": "Название объекта",
    "district": "ЦАО"
  }
}
```

Точный список 14 признаков хранится в `model/metadata.json`; готовые полные
примеры находятся в `example_input.json` и `example_alert_input.json`. Рабочий
API требует текущую московскую дату. Исторический пример разрешается только при
явном `ML_ALLOW_HISTORICAL_SCORING=1`.

## Файлы

- `model/fire_risk_7d_seed_*.cbm` и `model/fire_risk_3d_seed_*.cbm` — ансамбль;
- `model/metadata.json` — схема, порог, веса, метрики и ограничения;
- `model/object_*.json` — объектные маппинги и константы;
- `infer.py` — строгая проверка входа и инференс;
- `adapter.py` — преобразование результата в общий контракт сайта.
